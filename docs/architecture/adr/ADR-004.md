# ADR-004: Auth0 identity and JWT validation

* **Status:** Approved
* **Date:** 2026-11-27
* **Depends on:** DEC-03, MA-05, SPEC-F01 OQ-1, CON-05 C05-OQ-01

## Context

GoJudge needs a trusted identity provider and API-side validation of access tokens. The application must keep authentication separate from authorization: a valid identity token does not itself grant application roles or permissions.

## Decision

Auth0 is the approved identity provider under DEC-03. The Go API uses `github.com/auth0/go-jwt-middleware/v3` as its authentication foundation. Auth0 is responsible for identity and JWT validation. PostgreSQL is the authoritative source of application roles and permissions; application privileges must not be granted solely from JWT role claims.

The SPK-02 successful Auth0 token-validation outcome is evidence for the provider and middleware choice. Its experimental administrator-role typo mapping and Resource Owner Password Flow are not adopted for production.

## Consequences

- F01 implementation follows the approved Auth0 and PostgreSQL authority boundary, subject to SPEC-F01 reviewer approval and the agreed CON-05 schema slice.
- Token validation and application role lookup remain distinct responsibilities.
- SPK-02 is supporting evidence, not approval of its experimental role mapping or sign-in flow.
